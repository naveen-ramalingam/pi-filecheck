# Pi FileCheck v0.1.1

Scans and file tests now default to **quick metadata prechecks**. The menu uses
quick checks only. These can detect damaged headers, missing end records and
known missing multipart volumes without reading/decompressing all file contents.
Readable metadata is UNKNOWN, never PASS. Payload corruption can remain undetected.
Quick checker calls are limited to 30 seconds; automatic hashing is disabled in
quick mode. Full tests remain available only through an explicit `--full` option.

Long archive checks now show activity every 10 seconds instead of remaining silent
until completion. The display includes elapsed time and, on Linux, approximate
validator bytes read. Each file's PASS/FAIL/UNKNOWN/SKIP/ERROR result appears as soon
as its check completes. JSON and CSV stdout remain parseable.

The interactive scan confirmation now uses the discovered file count and total
size. Unexpected-end diagnostics explicitly explain that an archive is truncated
or incomplete. No integrity test is weakened or replaced with identification.

Read activity is not a completion percentage. Large compressed archives can take
many minutes to verify. The existing timeout, interruption, read-only source
handling, checksum/reference distinction, and unsupported Sony-format behavior
remain in effect. This is a pre-1.0 release requiring Python 3.11+.
